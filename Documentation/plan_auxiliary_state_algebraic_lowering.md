# AuxiliaryState Algebraic Lowering Plan

## Goal

Allow boundary-condition and other `AuxiliaryState` models to be authored monolithically while avoiding a linear/nonlinear performance penalty when part or all of the auxiliary block is purely algebraic. The solver should:

- keep the monolithic authoring and FE assembly semantics,
- detect algebraic-only auxiliary unknowns generically,
- eliminate those algebraic unknowns exactly before the backend solve,
- export the exact reduced field operator/coupling to the linear solver,
- preserve true monolithic treatment only for genuinely dynamic auxiliary states.

This is the generalization needed so a resistance outlet, or any future algebraic-only `AuxiliaryState`, behaves like an exact reduced/direct feedthrough model inside BlockSchur rather than as a live bordered solve unknown.

## Scope

The plan covers:

- auxiliary metadata propagation from deployment/assembly to Newton,
- exact algebraic elimination of bordered auxiliary blocks,
- reduced-update / grouped reduced-coupling export to the backend,
- recovery of eliminated auxiliary increments after the linear solve,
- validation on the current fluid regression cases.

It does not change the author-facing modeling API for `AuxiliaryState`.

## Step 1: Classify Auxiliary Unknowns

Determine, for every bordered auxiliary unknown in solve order, whether it is:

- `differential`
- `algebraic`

The classification must be carried in the same mixed ordering used for the bordered `B`, `C`, `D`, and `g` blocks.

### Checklist

- [x] Extend bordered coupling metadata to store per-auxiliary-variable kind information.
- [x] Clear and resize this metadata together with the rest of `BorderedCouplingData`.
- [x] During bordered assembly, expand each deployed auxiliary model's variable-kind metadata into the actual solve ordering.
- [x] Preserve correct expansion for both `ByEntityThenComponent` and `ByComponentThenEntity`.
- [x] Verify algebraic-only resistance outlets are classified as algebraic in the assembled bordered system.

## Step 2: Partition Bordered Systems into Algebraic and Dynamic Pieces

Given the bordered linearization

- PDE row: `K du + B dx = r`
- auxiliary row: `C du + D dx = g`

partition `x` into algebraic and dynamic components:

- `x = [x_a, x_d]`

and correspondingly partition `B`, `C`, `D`, and `g`.

### Checklist

- [x] Build algebraic and dynamic index sets from the per-variable-kind metadata.
- [x] Extract dense sub-blocks `B_a`, `B_d`, `C_a`, `C_d`, `D_aa`, `D_ad`, `D_da`, `D_dd`, `g_a`, `g_d`.
- [x] Treat the reduction as inactive when no algebraic unknowns are present.
- [x] Treat the reduction as inactive when `D_aa` is singular or not factorizable.
- [x] Keep the original bordered solve path unchanged for the inactive case.

## Step 3: Eliminate Algebraic Auxiliary Unknowns Exactly

When `D_aa` is invertible, eliminate `x_a` exactly:

- `x_a = D_aa^{-1} (g_a - C_a du - D_ad x_d)`

which gives the reduced field/dynamic system:

- `K_eff = K - B_a D_aa^{-1} C_a`
- `r_eff = r - B_a D_aa^{-1} g_a`
- `B_eff = B_d - B_a D_aa^{-1} D_ad`
- `C_eff = C_d - D_da D_aa^{-1} C_a`
- `D_eff = D_dd - D_da D_aa^{-1} D_ad`
- `g_eff = g_d - D_da D_aa^{-1} g_a`

### Checklist

- [x] Factor `D_aa` robustly and apply it to the required right-hand sides.
- [x] Form the exact reduced field correction `-B_a D_aa^{-1} C_a`.
- [x] Form the exact reduced field RHS shift `-B_a D_aa^{-1} g_a`.
- [x] Form the reduced dynamic bordered blocks when dynamic auxiliary unknowns remain.
- [x] Leave no live bordered unknowns for algebraic-only systems after reduction.
- [x] Preserve grouped exact coupling information for multi-mode algebraic reductions.

## Step 4: Export the Reduced Operator to the Backend

The backend should see the exact reduced linearized operator, not the unreduced bordered system for algebraic-only models.

### Checklist

- [x] Append exact reduced field updates generated by algebraic elimination to the active reduced-update set used by the backend.
- [x] Append grouped bordered reduced couplings for multi-mode algebraic reductions.
- [x] Promote exact independent algebraic reductions to native rank-one updates when mathematically valid.
- [x] Switch the live bordered system handed to the linear solver from the original full block to the reduced dynamic-only block.
- [x] Keep nonlinear convergence bookkeeping tied to the full physical bordered residual, not only the reduced solve representation.

## Step 5: Recover Eliminated Auxiliary Increments After the Solve

After the reduced field/dynamic solve, reconstruct the eliminated algebraic increment exactly:

- `dx_a = D_aa^{-1} (g_a - C_a du - D_ad dx_d)`

and then reassemble the full auxiliary increment in original ordering.

### Checklist

- [x] Recover eliminated algebraic auxiliary increments after each linear solve.
- [x] Reconstruct the full auxiliary delta in the original bordered ordering.
- [x] Feed the reconstructed full auxiliary update into the normal auxiliary-state update path.
- [x] Ensure Newton recovery / post-step state updates use the full auxiliary increment, not the reduced one.

## Step 6: Keep Monolithic Authoring Semantics

Model authors should still be able to define algebraic outlet and boundary models as `AuxiliaryState` systems. The solver lowering pass should decide whether they remain monolithic solve unknowns.

### Checklist

- [x] Restore `C=0` resistance outlets to monolithic `AuxiliaryState` authoring semantics using the summed resistance model.
- [x] Remove the need for a solver-level direct-coupling factory special-case for algebraic resistance outlets.
- [x] Preserve true monolithic treatment for dynamic models such as `RCR` with nonzero capacitance.

## Step 7: Validation

Validation must show that the generic lowering path is algebraically correct and does not regress the main fluid benchmarks.

Current status:

- `pipe_simple` and `pipe_RCR_3d` are healthy on the generic monolithic lowering path and remain below the old detached `67c12fe` baseline in the latest stable subset reruns.
- `iliac_artery` still fails to converge on the generic monolithic lowering path (`step=0`, `iters=12`, no completed time step), so full Step 7 signoff is still blocked.
- The remaining blocker is no longer the algebraic-lowering infrastructure itself. The monolithic path now reduces to exact algebraic elimination and stable native outlet updates, but the `iliac_artery` case still needs additional solver work beyond this plan.

## Expected Outcome

After this plan is complete:

- algebraic-only `AuxiliaryState` models remain monolithic at the modeling layer,
- the solve layer lowers them automatically to exact reduced coupling,
- BlockSchur does not pay a bordered-solve penalty for algebraic-only auxiliary blocks,
- future algebraic-only auxiliary models inherit the same fast path without new solver-specific special-casing.
